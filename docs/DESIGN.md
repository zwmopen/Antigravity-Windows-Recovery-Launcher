# 设计与原则

## 初衷与真实问题

为 Cockpit 多账号切换后的 Antigravity 自动检查专用代理、清除黑屏实例并恢复启动。

## 服务对象

AI基础设施与 Windows 工作环境

服务本机 AI 基础设施。没有它时，Cockpit 切号会再次启动无代理实例，造成黑屏、消息无回复或地区限制误判，并让用户反复手工重启。

## 目标用户与使用场景

使用 Cockpit Tools 管理多个 Antigravity 账号、希望双击一次完成恢复的 Windows 用户。

## 成功标准

- 桌面只保留一个稳定 EXE 入口。
- 切号或 `--reuse-window` 覆盖后自动恢复为带 `17897` 的唯一主进程。
- language server 只连接专用代理，不直连 Google 443。
- 不删除登录态、会话、项目或修改全局 `7897`。

## 核心原则

1. 用户视角：入口、状态、结果和风险自解释。
2. 本地优先：用户数据默认由用户控制。
3. 可恢复：高风险操作有备份、回滚或安全降级。
4. 克制：按项目规模实现，不为显得完整而堆功能。

## 关键取舍

| 选择 | 原因 | 放弃什么 | 何时重新评估 |
|---|---|---|---|
| 独立小应用，不立即并入个人聚合工具箱 | 先稳定真实高频故障，缩小变更面 | 暂无统一工具箱界面 | 小应用长期稳定后再评估 |
| EXE + PowerShell 监督器 | EXE 提供稳定入口和进度，PowerShell 保留可审计系统修复 | 不是单一原生二进制 | 跨电脑分发时再封装安装器 |

## 放大逻辑

每次运行自动校验入口和代理链；后台监控把 Cockpit 的重复覆盖故障机械化修复。故障模式沉淀在项目文档中，方便后续电脑复用。

## 明确不做什么

- 不修改 Google 账号国家、付款资料或身份信息。
- 不绕过账号地区资格和 Google 风控。
- 不修改 Clash 全局代理 `7897`。
- 不自动发送测试消息，不操作验证码和登录授权。
