# 设计与原则

## 初衷与真实问题

为 Cockpit 多账号切换后的 Antigravity 自动检查专用代理、清除黑屏实例、恢复启动，并以外部扩展提供可逆的简体中文 UI。

## 服务对象

AI基础设施与 Windows 工作环境

服务本机 AI 基础设施。没有它时，Cockpit 切号会再次启动无代理实例，造成黑屏、消息无回复或地区限制误判，并让用户反复手工重启。

## 目标用户与使用场景

使用 Cockpit Tools 管理多个 Antigravity 账号、希望双击一次完成恢复的 Windows 用户。

## 成功标准

- 桌面只保留一个稳定 EXE 入口。
- 切号或 `--reuse-window` 覆盖后自动恢复为带 `17897` 的唯一主进程。
- language server 只连接专用代理，不直连 Google 443。
- 专线上游持续断流时，在不触碰 Clash 日常状态的前提下自动轮换已发现候选并恢复。
- 不删除登录态、会话、项目或修改全局 `7897`。

## 核心原则

1. 用户视角：入口、状态、结果和风险自解释。
2. 第一性原理与极致简单：拒绝过度设计与技术自嗨。用户点击的核心意图是“写代码”，不是看测速面板、挑节点或排查握手。日常 0 思考秒进，故障一键无脑自愈，底层把所有脏活累活默默做完。
3. 说人话与对齐美学：按钮和状态拒绝工单技术腔（严禁类似“重新优选线路并修复”等冗长极客词）。坚持 4 字工整对仗（如 `直接打开` vs `重启修复`），动词先行，排版居中且呼吸感充裕。
4. 本地优先：用户数据默认由用户控制。
5. 可恢复：高风险操作有备份、回滚或安全降级。
6. 克制：按项目规模实现，不为显得完整而堆功能。
7. 外部无侵入：不改 `app.asar` 或 preload；汉化只存在于带启动参数的当前运行实例。

## 关键取舍

| 选择 | 原因 | 放弃什么 | 何时重新评估 |
|---|---|---|---|
| 独立小应用，不立即并入个人聚合工具箱 | 先稳定真实高频故障，缩小变更面 | 暂无统一工具箱界面 | 小应用长期稳定后再评估 |
| EXE + PowerShell 监督器 | EXE 提供稳定入口和进度，PowerShell 保留可审计系统修复 | 不是单一原生二进制 | 跨电脑分发时再封装安装器 |
| 外部词库 + CDP Loader，保留 MV3 回退 | 词库和 DOM 逻辑可审查、可移除，并兼容当前 2.11.0 忽略 `--load-extension` 的现实行为 | 依赖 Antigravity 继续暴露本地 DevTools 目标 | 目标版本关闭调试目标或更换本地 UI 协议时 |
| 粘性主节点 + 有界故障转移 | 稳定时不换 IP；连续网络失败或新地区 400 才切换，失败节点冷却 | 不追求最低延迟，也不保证任意美国节点有模型资格 | 当前订阅候选长期不足或均被 Google 拒绝时 |

词库维护采用“完整句子优先、短词按 UI 上下文启用”的边界。这样能覆盖 Settings 的长说明，又不会把 `General Greeting Conversation` 一类用户标题改成混合语言；公开项目只作为文案参考，当前 Loader、恢复和代理链保持不变。

## 放大逻辑

每次运行自动校验入口和代理链；后台监控把 Cockpit 的重复覆盖故障机械化修复。故障模式沉淀在项目文档中，方便后续电脑复用。

## 明确不做什么

- 不修改 Google 账号国家、付款资料或身份信息。
- 不绕过账号地区资格和 Google 风控。
- 不修改 Clash 全局代理 `7897`。
- 不刷新订阅、不调用 Clash 自动选择、不切换规则/全局/直连模式或日常节点。
- 只在启动或真实故障恢复时通过官方 CLI 发送固定的最小 `OK` 生成探针；不使用用户正文、不调用工具、不修改文件，不做高频心跳。
- 不操作验证码和登录授权；官方 CLI 必须复用用户已存在的系统 keyring 登录态。
- 不把翻译脚本注入第三方网站；扩展只匹配 `127.0.0.1` 和 `localhost` 的本地 UI 地址。
- 不翻译用户消息、模型输出、代码、终端内容或可编辑输入，避免改变工作数据。
