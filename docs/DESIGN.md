# Antigravity 智能启动器 · 设计哲学与工程原则

> “用户双击启动器的终极意图是**专注写代码**，而不是成为一名排查代理握手、测试节点延迟、天天重启软件的网管。”

---

## 1. 核心定位与第一性原理

Antigravity 智能启动器并非一个臃肿的“通用代理客户端”，而是专为 **Google Antigravity AI 编程 IDE** 量身定制的工业级自愈底座与启动入口。

### 第一性原理（First Principles）
1. **心流神圣不可侵犯（No-Kill Rule）**：
   在任何情况下，只要 Antigravity 正在正常响应，系统**绝对不能为了切换专线而强杀编辑器进程**！用户的未保存草稿、终端任务、会话上下文远比重启更重要。专线切换必须在内存与代理沙盒中毫秒级无感热漂移完成。
2. **零思考与无感交互（Zero Cognitive Overhead）**：
   日常状态下双击即进，3 秒无操作自动呼出代码窗口；出现网络卡顿或节点失效时，用户只需一键点击“⚡ 切换最优专线”，底层默默把脏活累活全部干完。
3. **真实物理铁证（Physical Verification Gate）**：
   拒绝虚假的 HTTP Ping 或简单的 TCP 握手。判定一个专线是否可用，必须通过 Google 官方 `agy` 命令行发送探针，以真实的 Gemini 模型返回 `OK` 作为准入门禁。

## 2. 界面设计美学：“既说人话，又极其专业”

很多技术工具往往走向两个极端：要么充斥着晦涩难懂的极客术语（如“重构 TUN 规则链并刷新 DNS 缓存”），要么简陋得像个玩具。本项目坚持**“人话表层 + 工业内核”**的设计平衡：

* **人话优先的微文案**：
  - 左按钮：`进入代码窗口 (3s)` —— 意图极其清晰，带 3 秒倒计时自动进入，给用户充分的确定感；
  - 右按钮：`⚡ 切换最优专线` —— 动词先行，直击结果，告别冷冰冰的“故障恢复”或容易引起误解的“重启”。
* **呼吸感与对齐美学**：
  - 采用现代 Windows 11 微光圆角风格与 GDI+ 矢量平滑抗锯齿；
  - 左右按钮 212×46px 完美对称，间距与边距经过像素级调优；
  - 运行状态用胶囊徽标展示（如 `美国专线就绪`、`● 运行中`），一目了然。

## 3. 架构取舍与工程边界 (Engineering Trade-offs)

| 决策点 | 我们的选择 | 为什么这么选？ | 放弃了什么？ |
| :--- | :--- | :--- | :--- |
| **沙盒隔离** | 独占 `127.0.0.1:17897` 独立端口 | 彻底杜绝与用户日常 Clash（7897）冲突，互不干扰 | 需要在后台额外拉起一个极轻量的专用内核实例 |
| **订阅解耦** | 穿透 `%APPDATA%` 直接提取 YAML 节点 | 客户端安装在 C 盘还是 D 盘根本不重要，真正需要的是订阅节点 | 不支持直接解析未导入客户端的裸订阅链接（必须先导入一次客户端） |
| **热切换机制** | 仅刷新沙盒上游链路，不杀编辑器进程 | 彻底保护正在编写的代码与会话，实现零打扰 | 需要处理底层长连接复用与优雅重路由 |
| **汉化方案** | CDP 动态桥接 + 首帧微任务直译 | 不改动官方 `app.asar`，安全防封，且彻底解决 1 秒翻页闪现感 | 依赖 Antigravity 开放的 DevTools 调试端口 |

## 4. 严苛的“底线红线”（明确不做什么）

为保障长期的安全性与系统稳定性，本项目在源码级别树立了不可逾越的红线：
* ❌ **绝不篡改官方二进制**：不解包或篡改 Antigravity 的 `app.asar` 或系统文件；
* ❌ **绝不触碰全局网络**：绝不开启 TUN 虚拟网卡，绝不篡改 Windows 系统代理或日常 Clash 的分流规则；
* ❌ **绝不窃取或上传凭证**：所有订阅解析、状态检测均在本地内存中完成，日志对 Token、密码、UUID 进行全面脱敏；
* ❌ **绝不污染用户工程**：绝不扫描或修改用户的代码文件、Git 仓库或对话内容。
