# 独立候选探测与受控接管

状态：已按用户确认实施并扩展正式 17897 二次模型门禁；当前待新一轮实机验收。基线：ecc9b3d，版本 1.6.6。

## 目标

消除候选轮询期间停止正式 17897 监听器导致的 connection refused。保护日常 7897、账号凭据、编辑器及用户会话。

## 方案与取舍

采用独立探测实例，验证成功后才更新正式代理。相比继续复用 17897，增加一个短生命周期进程，但测试失败不影响正式监听；相比增加永久前置网关，改动范围较小，不引入第三个常驻服务。

探测端口从回环地址可用端口中分配，占用即重新分配；单独目录、配置、PID、日志。清理只针对本轮拥有且路径与 PID 匹配的实例。保持已有监督器互斥锁，禁止并行恢复抢占。

## 流程

1. 读取最新有效订阅，在内存中生成候选列表，US/JP 同池，优先新鲜低延迟。不刷新日常 Clash 订阅。
2. 启动独立候选代理；通过明确指向测试端口的网络、出口和官方 AGY 真实生成验证。测试不覆盖正式配置或 ready 状态。
3. 候选失败：记录失败种类、清理测试实例、继续有界候选轮询；17897 PID 和配置不变。
4. 候选成功：保留正式配置备份，进入单次接管事务。正式 17897 启动后再次执行同一真实模型门禁；只有正式门禁通过才允许写入 ready。能复用现有内核受控重载能力则重载；否则只在接管阶段重启一次正式代理。明确允许短暂重连，不承诺已有流式请求无损迁移。
5. 接管失败：恢复原配置与正式监听，状态标为 degraded，不伪报模型恢复。全部候选失败也保留原监听；原线路已坏时明确标为不可用。
6. 成功后清理探测实例，更新正式状态与事件。不同状态分别记录 probing、promoting、ready、degraded。

## 验收

- Windows PowerShell 5.1 和当前 PowerShell 全文件语法检查。
- 注入至少两个失败候选，正式测试监听 PID、端口与长连接保持不变。
- 候选成功前不得调用正式停止/写配置；成功只接管一次。
- 模拟接管失败验证备份回退；取消与异常均只清理自有测试进程。
- 探针的实际代理必须是测试端口，不允许环境变量回落到 7897/17897。
- 对真实候选运行有界 AGY SUCCESS + OK 验证；部署前后校验哈希、系统代理及 7897 不变。
- 节点端外部故障无法由代码保证消除；测试未通过的部分必须明确列为未验收。

## 非目标

本轮不修改额度算法、模型切换、自动续接、登录态，也不替换官方 Antigravity。仅升级代理候选探测和接管流程。
