## 🎯 核心解决痛点

在使用 Google Antigravity 进行高强度 AI 辅助编程时，开发者通常面临以下几大心流杀手：

1. **夜间/无人值守切入坏号导致死锁**：普通切号工具因只看本地评分，容易将编辑器切入已被封禁、需要手机网页验证或需申诉的失效账号（如遇到 `invalid_grant` / `This service has been disabled`），导致清晨醒来发现客户端卡死、不断报错弹窗；
2. **算力额度浪费（天数多反抢天数少）**：传统调度往往只看当前剩余额度，导致周额度还剩 2 天就要刷新的账号被闲置，反而去消耗周额度刚重置（还有 6 天）的账号，造成即将刷新的周额度彻底浪费；
3. **传统工具粗暴杀进程**：市面上的工具动辄使用任务管理器强制杀死 Antigravity 进程，导致未保存的代码草稿、正在运行的长任务终端全部毁灭；
4. **隔离账号无法恢复**：账号一旦被系统封禁或判定异常，缺乏便捷的解封与状态恢复机制，无法在完成人工申诉或重新登录后重新纳管。

**Antigravity 启动器与调度引擎（v2.9.1）正是为了终结这一切痛点而设计。**

## 🌟 五大核心技术支柱

### 1. 🧠 四级优先级智能算力调度算法
调度引擎对账号池建立科学的四级决胜模型，确保每一分算力都被榨取在最高性价比区间：
* **第 1 优先级：周额度到期时间（越近越优先）**  
  > **核心逻辑**：若有两个账号 A（周重置剩余 2 天，额度 23%）与 B（周重置剩余 6 天，额度 99%），系统**绝对优先使用账号 A**！因为 A 的额度马上就要刷新，不消耗就彻底浪费；
* **第 2 优先级：可用额度存量（同一重置天数梯队内，额度越多越优先）**  
  > 额度存量必须大于 5%（小于等于 5% 判定为濒死账号，自动踢出可用池）。在重置时间相近的梯队内，额度更充裕的账号优先胜出；
* **第 3 优先级：小时额度状态（越满血越优先）**  
  > 在周额度条件相当时，优先选择 5 小时短周期额度处于 100% 满血的账号，保障单次高强度会话的充沛爆发力；
* **第 4 优先级：异常状态一票否决与封禁跳过**  
  > 命中 Google 封禁、提示“需要申诉”、需要二次验证或发生 `invalid_grant` 的账号，实施**一票否决**，扣除 100,000 惩罚分，永远不可能被智能切入。

---

### 2. 🛡️ 冷启动零信任前置门禁（Preflight Gate）
用户通过桌面快捷方式启动 Antigravity 时，启动器不盲目拉起客户端，而是先执行 `--preflight-ensure` 零信任前置校验：
* **启动前深度预检**：读取当前主账号本地凭据与状态；
* **坏号秒级自愈拦截**：若检测到当前准备启动的账号属于封禁黑名单、429 关押或异常失效账号，启动器**在唤醒编辑器窗口之前**，直接在后台原子切换到健康的全局最优账号；
* **彻底根除启动死锁**：确保用户双击进入编辑器时，永远呈现一个可直接调用模型写代码的健康工作环境。

---

### 3. 🚫 动态黑名单与一键解封机制（账号隔离中心）
系统内置四重隔离联动体系，兼顾自动安全防护与人工自由纳管：
* **多层隔离机制**：
  - **永久硬黑名单 (`hard-blocked-emails.json`)**：封禁、失效或人工指定拉黑的账号；
  - **429 临时关押池 (`quarantined-accounts.json`)**：短时间频控限制的账号，冷却期间自动跳过；
  - **Cockpit AES-GCM 加密账户明细**：同步标记 `disabled: true` 与详细错误原因。
* **一键无缝解封（CLI）**：
  - 用户在 Google 网页端完成账号申诉、解除验证或重新授权后，仅需一条命令即可实现**跨文件级四重全自动解封**，立刻重新纳管参与算力调度。

---

### 4. 🪟 前台拟态算力透明看板（四行核心链路监控）
冷启动或切换状态时，桌面呈现极简胶囊看板，毫秒级自检并直观呈现四大基础设施指标：
1. **本地专线沙盒**：`127.0.0.1:17897` 独立代理端口联通状态；
2. **Google 链路**：Google API 专线延迟（RTT ms）与当前接管的节点名称；
3. **AI 模型服务**：真实 Gemini 模型生成探活，拒绝虚假 TCP Ping；
4. **算力调度中心**：当前活跃账号邮箱、5 小时额度比例、周额度比例及距周重置剩余天数。

---

### 5. ⚡ 无感热切换与独立沙盒（绝不杀编辑器）
* **生命周期无感**：专线切换、节点重路由全部在后台 `17897` 沙盒内部完成，正在编写的文件、光标位置、未提交的 Git 状态与终端进程 **100% 保持常驻**；
* **日常代理零污染**：独占 `17897` 端口，不篡改系统全局代理，不占用 Clash 默认的 `7897` 端口，日常浏览网页与游戏不受丝毫干扰。

### 2. 🔓 如何将已黑名单的账号解封放出？
当你在 Google 官网申诉成功、解除手机验证或重新登录之后，想要将该账号**重新加入算力调度候选池**：

只需执行一条解封命令：
```bash
# 语法：
.\src\Antigravity-QuickSwitch.cmd --unblock <账号邮箱或ID>

# 例如解封 azrimjs@gmail.com：
.\src\Antigravity-QuickSwitch.cmd --unblock azrimjs@gmail.com
```

**系统底层全自动完成以下四重解封动作**：
1. ✅ **永久黑名单出狱**：从 `hard-blocked-emails.json` 彻底抹除；
2. ✅ **429 临时关押释放**：从 `quarantined-accounts.json` 冷却池中立即释放；
3. ✅ **Cockpit 加密明细解封**：使用 AES-GCM 算法解密 `.antigravity_cockpit/accounts/<id>.json`，将 `disabled` 改回 `false`，并清空所有历史报错标记（`disabled_reason`, `quota_error`, `token_error`），重新加密写入；
4. ✅ **全局索引与 UI 同频**：同步更新 `.antigravity_cockpit/accounts.json` 索引，触发 Cockpit UI 自动刷新。该账号立即满血回归智能调度候选池！

---

### 3. 🚫 如何手动将某个异常账号拉入黑名单？
如果你发现某个账号暂时不能使用或想要人工隔离，可直接执行：
```bash
.\src\Antigravity-QuickSwitch.cmd --block <账号邮箱> "隔离原因说明"

# 示例：
.\src\Antigravity-QuickSwitch.cmd --block bad_acc@gmail.com "账号等待人工换绑"
```
被拉黑的账号将立刻退出调度池，调度引擎绝不会再将其切入编辑器。

## ❓ 常见问题解答 (FAQ)

### Q1: 为什么要坚持“周到期时间越近越好”，而不是只看剩余额度？
**A**: Google Antigravity 的周额度按固定周期刷新，**未用完的额度到期即作废，不会滚存**。  
假设账号 A 还有 2 天就重置，即使只剩 30% 额度，也应当优先消耗完毕；若此时去消耗刚重置（还有 6 天）的账号 B，2 天后账号 A 刷新，之前剩余的 30% 额度就彻底蒸发了。因此，优先消化即将到期的账号是算力价值最大化的核心策略。

### Q2: 之前被系统黑名单拦截的账号，申诉回来后怎么放出来？
**A**: 只需在命令行中执行 `.\Antigravity-QuickSwitch.cmd --unblock <邮箱>` 即可。系统会自动从硬黑名单、429 临时关押名单中移除该账号，并自动解密重置 Cockpit 中的 `disabled` 状态为正常，账号立刻回到可用调度池中。

### Q3: 智能切号与专线切换会和我的 Cockpit 工具冲突吗？
**A**: 绝对不会。调度引擎与 Cockpit 深度兼容，共享同一套 AES-GCM 安全凭据目录并遵循文件锁协议。调度引擎切号完成后，会自动触发 Cockpit 界面刷新，保持双端状态完全同步。

### Q4: 切换账号时会丢失我正在写的代码或会话吗？
**A**: 不会。调度引擎通过精准更新状态与平滑热加载完成，绝不使用任务管理器杀死主编辑器进程，你的编辑窗口、未保存草稿与正在运行的终端任务均得到完整保护。
